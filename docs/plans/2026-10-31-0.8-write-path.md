# 0.8 Write Path Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Writes to the TRVZB stop producing false "not responding" notices: zigpy gets to finish its own retries, the device's write response counts as verification, the Repairs notice waits an hour, and settings the device already has are not written again.

**Architecture:** Four independent changes along the write path: a constant (`const.py`), the controller's write-and-verify step (`controller.py`, `profiles/engine.py`, the gateway adapter), and the pure room logic that decides when a failing thermostat becomes visible (`core/model.py`, `core/room_logic.py`, `core/room_state.py`), plus the Repairs text (`issues.py`, translations).

**Tech Stack:** Python 3.14, Home Assistant 2026.10 custom integration, zha 2.3.1 / zigpy 2.3.0, pytest with `pytest-homeassistant-custom-component`.

**Spec:** `docs/specs/2026-10-31-easy-trv-0.8-write-path-design.md`

## Global Constraints

- `OPERATION_TIMEOUT` = 180 s (spec A).
- Read back only when `observe or signals or also_read` (spec B); a failed read-back is `Ok`, an `UNSUPPORTED_ATTRIBUTE` read is handled as today.
- Report delay 60 minutes, a constant `RoomParams.report_after`, no new setting (spec C). In tests, `report_after=timedelta(0)` means "report at the give-up itself", which keeps the existing tests' timing.
- `trv_unreachable` severity WARNING, placeholder `minutes` replaces `attempts` (spec C).
- Only `SETTING_INTENTS` consult the zigpy cache (spec D); a skipped setting is not counted as a write.
- Run tests with `.venv/bin/python -m pytest -q -p no:cacheprovider <path>`; lint with `.venv/bin/ruff check . && .venv/bin/ruff format --check .` and `.venv/bin/mypy custom_components` if configured in `pyproject.toml`. `tests/test_diagnostics.py::test_diagnostics_contains_rooms` fails in the cloud sandbox (socket blocked) before any change; ignore it.
- Commits end with the session's attribution lines; user-facing text in `strings.json`, `translations/en.json` (identical to `strings.json`) and `translations/de.json` (du-form, „…“ quotes).

## Review Focus

1. A thermostat that fails, recovers within the hour, and fails again: `failing_since` must restart from the second failure, not carry over the first. Test in Task 4.
2. A thermostat that is unavailable when the hour is over: no notice while it is away (health is UNAVAILABLE); the notice comes when it is back in error past the hour. Test in Task 4.
3. A reported thermostat that recovers: `failing_since` and `issue_raised` are reset, a later failure waits a fresh hour. Test in Task 4.
4. A zigpy cache holding a non-int zigpy type (`t.Bool`, enum, bitmap) for a setting: `cached` must return a plain `int` so `in op.accept` compares correctly. Test in Task 3.
5. The read-back of `external_temperature` failing while the write succeeded: no retry, no `write_failures` count, the value still counts as written for the refresh clock. Test in Task 2.
