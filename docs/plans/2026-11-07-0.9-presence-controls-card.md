# Easy TRV 0.9 — Presence controls and the card — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Away counts only after a delay, the house can force home/away, rooms expose window and presence as binary sensors, the global setback is a number that applies without a reload, and a card bundled with the integration shows and controls all of it.

**Architecture:** The room core is unchanged except for one event `SettingsChanged(away_setback)`; delay and forcing live on the Home Assistant side and decide what `PresenceChanged` is fed. A new `HousePresence` (one per entry, in `runtime_data`) holds the forced option; each room's `PresenceInput` asks it first, then applies its own delay. New platforms `select`, `number`, `binary_sensor` on a new house device and the room devices. The card is one plain JS web component served by the integration and loaded with `frontend.add_extra_js_url`.

**Tech Stack:** Python 3.14, Home Assistant custom integration, pytest + pytest-homeassistant-custom-component, ruff, mypy; vanilla JavaScript (custom elements, no build step).

**Spec:** `docs/specs/2026-11-05-easy-trv-0.9-presence-controls-design.md`

## Global Constraints

- `core/` imports nothing from `homeassistant`.
- New setting `away_delay_minutes`: options only (section Presence), 0–120, step 1, default 15; `0` = away at once.
- Select `select.easy_trv_presence`, options `auto` / `home` / `away` (EN Automatic / Home / Away, DE Automatisch / Zuhause / Abwesend), unique id `{entry_id}_presence`.
- Number `number.easy_trv_away_setback`, 0.5–10 K, step 0.5, mode box, `entity_category` config, unique id `{entry_id}_away_setback`; writes the global option `away_setback_kelvin`.
- Binary sensors `binary_sensor.<room>_window` (device class window, unique id `{subentry_id}_window`) and `binary_sensor.<room>_presence` (device class presence, unique id `{subentry_id}_presence`), `entity_category` none.
- House device: identifiers `{(DOMAIN, entry_id)}`, manufacturer and name "Easy TRV".
- Bus event `easy_trv_presence_forced`, data `{"option": "auto"|"home"|"away", "reason": "user"|"presence_changed"}`.
- Live option keys (no reload): `away_setback_kelvin`, `away_delay_minutes`.
- Card: file `custom_components/easy_trv/frontend/easy-trv-card.js`, URL `/easy_trv/easy-trv-card.js?v=<manifest version>`, element `easy-trv-card`, editor `easy-trv-card-editor`, options `rooms`, `house` (default true), `statistics` (default true).
- Texts: `strings.json` = `translations/en.json`; `translations/de.json` du-form, „…“ quotes.
- Gate per task: `.venv/bin/python -m pytest -q`, `.venv/bin/ruff check .`, `.venv/bin/ruff format --check .`; mypy may not get worse than the 10 known errors (`.venv/bin/mypy custom_components`).
- Commits: conventional subjects, end with the session's attribution lines. Implementers never push.

## Review Focus

- HA restarts while the select says Away and the person came home during the downtime: the select must be Automatic after start (Task 3 test `test_restore_with_changed_presence_returns_to_auto`).
- HA restarts while the person has been away for 3 h: rooms must be away at once, not after another 15 min (Task 2 test `test_start_away_since_long_counts_at_once`).
- Setback changed in the card while a room has an away override: the room keeps heating to its override, nothing is written (Task 5 test `test_settings_changed_with_override_writes_nothing`).
- Options form saved with only the setback changed must not reload; with any other change it must (Task 5 tests `test_live_keys_apply_without_reload`, `test_other_change_reloads`).
- Integration reloaded several times: the card module is registered once, not stacked (Task 6 test `test_card_registered_once_across_reloads`).
