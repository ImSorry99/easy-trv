# Easy TRV 0.6 — Statistics — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Collect data Home Assistant does not record by itself (writes and failed writes per thermostat) and keep derived values (deviation, heating time, window openings and open time, dropouts) as long-term statistics.

**Architecture:** A pure accumulator in `core/statistics.py` holds counters and running durations. The controller feeds it from the places it already sees writes, outcomes, availability changes, raw window edges and the thermostats' `hvac_action`. Diagnostic `RestoreSensor` entities read it and restore their last totals into it at start.

**Tech Stack:** Python 3.14, Home Assistant 2026.10 custom integration, pytest with pytest-homeassistant-custom-component, ruff, mypy, uv.

**Spec:** `docs/specs/2026-10-15-easy-trv-0.6-statistics-design.md`

## Global Constraints

- `core/` imports nothing from `homeassistant`.
- All new entities: `entity_category: diagnostic`, on the room device, `has_entity_name`, translated names in `strings.json` / `translations/en.json` / `translations/de.json` (`strings.json` identical to `en.json`).
- Counters and durations: `state_class: total_increasing`, never decrease, continue after a restart.
- Durations in hours (`UnitOfTime.HOURS`, device class `duration`, suggested display precision 2); deviation in K (unit `"K"`, no device class, `state_class: measurement`, precision 1).
- Room keys: `deviation`, `heating_time`, `window_openings`, `window_open_time`. Thermostat keys: `writes`, `write_failures`, `dropouts`.
- Unique ids: room `<subentry_id>_<key>`; thermostat `<subentry_id>_<climate object id>_<key>`. Suggested entity ids: room `sensor.<slug(title)>_<key>`, thermostat `sensor.<climate object id>_<key>`.
- Gate per task: `UV_CACHE_DIR=.uv-cache uv run pytest -q`, `UV_CACHE_DIR=.uv-cache uv run ruff check .`, `UV_CACHE_DIR=.uv-cache uv run ruff format --check .`, `UV_CACHE_DIR=.uv-cache uv run mypy` all clean.
- Commits: author ImSorry99 noreply; **no** `Co-Authored-By`, no Claude/AI mention; conventional subjects.

## Review Focus

1. A restart in the middle of a running duration (window open, TRV heating): no time is lost beyond the downtime and nothing is counted twice; restored totals never decrease.
2. A thermostat that never reports `hvac_action`: the heating-time sensor is unavailable, not stuck at 0 and not an error.
3. A contact that flaps or reports `on` repeatedly: one opening per closed→open edge; silent contacts follow their resolved state.
4. A write that is never sent (device unavailable, profile cannot plan it): not counted as a write or failure.
5. A room reload (options change): totals continue from the sensors' restored values, entities are not duplicated, listeners are released.

### Task 1: Pure accumulator and deviation

**Files:** Create `custom_components/easy_trv/core/statistics.py`; test `tests/core/test_statistics.py`.

**Interfaces (produces):**
- `@dataclass(frozen=True) class Duration`: `total: float` (seconds, finished periods), `since: datetime | None` (running start). Methods/functions: `start(d, now) -> Duration` (no-op if running), `stop(d, now) -> Duration` (adds `now - since`, no-op if stopped), `seconds(d, now) -> float` (total plus the running part), `restored(d, seconds: float) -> Duration` (raises `total` to at least `seconds`, never lowers it).
- `def deviation(state: RoomState, config: RoomConfig, now: datetime) -> float | None`: the active sensor's value minus `state.setpoint`, rounded to 0.1, only when `room_operation(state)` is HEAT and no hold is active (`window_open` / `outdoor_hold` false) and both values exist; else `None`.

### Task 2: Controller feeds the statistics

**Files:** `custom_components/easy_trv/controller.py`, `custom_components/easy_trv/observation.py`; tests `tests/test_controller.py` (or a new `tests/test_statistics_feed.py`).

**Interfaces (produces):**
- `RoomController.statistics(now: datetime | None = None) -> RoomStatistics` where `RoomStatistics` (frozen dataclass, HA side) has `deviation: float | None`, `heating_hours: float | None` (None when no thermostat of the room has an `hvac_action` attribute), `window_openings: int | None` and `window_open_hours: float | None` (None for rooms without contacts), and `per_thermostat: Mapping[str, ThermostatStatistics]` with `writes: int`, `write_failures: int`, `dropouts: int`.
- `RoomController.restore_statistic(key: str, value: float, thermostat: str | None = None) -> None`: seeds a total from a restored sensor value (counters: max of current and restored; durations via `restored`).
- Counting rules (spec 2): a write counts when `_write_and_verify` actually sent a write request (not when planning failed or the device was unavailable before sending); a failure counts for `Failed` or `Mismatch` from a sent write; a dropout counts on the available→unavailable edge already seen in `_handle_state_change`; a window opening counts on the raw all-closed→any-open edge of `HoldInputs` (before the delay; add a raw-edge callback to `HoldInputs`); heating time runs while any of the room's thermostat climate entities has `hvac_action == "heating"` (state-change listener on the climate entities, read the attribute; track whether any has the attribute at all).
- Update listeners are notified on every change, and a 60-second interval (`async_track_time_interval`, released on stop) notifies while a duration runs.

- [ ] Tests first for every counting rule and Review Focus 3 and 4, the 60-second notification, release on stop. Watch fail, implement, pass, full gate.
- [ ] Commit `feat: count writes, failures, dropouts, window openings and heating time`.

**Interfaces (consumes Task 2).** Room sensors only for rooms where the value exists (no window sensors without contacts; heating time created always, unavailable while `heating_hours is None`). Each sensor is a `RestoreSensor`: in `async_added_to_hass` it restores its last native value into the controller via `restore_statistic` before its first write, then listens with `add_update_listener`.
