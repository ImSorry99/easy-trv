# Easy TRV 0.5 — Room State, Silent Contacts, Areas, Hidden Entities — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make each room's heating situation visible (state sensor, silent-contact issue), put a room's Easy TRV entities into its area, and optionally hide the thermostat entities Easy TRV controls; release 0.5.0.

**Architecture:** A pure `core/room_state.py` turns facts about the room into one state plus all reasons; the controller builds the facts, keeps `since`, fires the change event and publishes. Hold inputs expose the window delay and raise a Repairs issue for contacts that stay silent. Area assignment and entity hiding run in `async_setup_entry` after the rooms are built, against the device and entity registries.

**Tech Stack:** Python 3.14, Home Assistant 2026.10 custom integration, pytest with pytest-homeassistant-custom-component, ruff, mypy, uv.

**Spec:** `docs/specs/2026-10-15-easy-trv-0.5-room-state-design.md` (sections A–G). Phase 2 spec `docs/specs/2026-10-14-easy-trv-phase2-design.md` stays valid where this one is silent.

- State values in this exact order: `fault, off_manual, off_window, off_outdoor, off_away, window_pending, emergency, restricted, boost, frost, heating`.
- Thermostat deviation values in this exact order: `error, unavailable, unsupported, schedule, window_phase`.

## Review Focus

1. A contact that flaps between `unavailable` and `on`/`off` every few seconds: the 10-minute timer restarts only when the silent set goes from empty to non-empty; no issue is raised unless contacts stay silent across the full 10 minutes.
2. A room reloaded or stopped while the silent-contact timer or the open delay is armed: no callback runs after `stop()`, and the issue is removed on stop.
3. A thermostat entity the person hid themselves (`hidden_by = user`) or an entity another integration hid: Easy TRV never marks or shows it.
4. A room whose stored `area_id` no longer exists in the area registry: setup and the reconfigure form work, nothing is assigned.
5. ZHA entity-registry entries with `translation_key = None` or on another platform on the same device: never matched for hiding.

Tests for each are named in the owning task.

Exactly one of `OFF_MANUAL`/`FROST`/`HEATING` is always in `reasons` (from `operation`).

Behaviour:
- `HoldInputs._open_after_delay` arming the timer, the timer firing and `_cancel_pending_open` cancelling an armed timer each call `self._changed()` (the firing path already feeds `WindowChanged`, which notifies; arming and cancelling must notify explicitly).
- `HoldInputs` arms a `CONTACT_SILENT_ISSUE_MINUTES` timer when the silent set goes from empty to non-empty, cancels it and clears the issue when the set becomes empty, raises the issue when it fires with contacts still silent, and re-raises with the new list when the set changes while the issue is raised. `contacts` = the contacts' state names (`state.name` when the state exists, else the entity id), sorted, joined by `", "`. `stop()` cancels the timer and clears the issue.
- `RoomController._notify_update` first recomputes the heating state from `state_facts(self._state, self._config, now, self._params.refresh, window_pending=self._holds.window_off_at is not None, silent_contacts=self._holds.silent_contacts)`. On a change from a previous value (not `None`) it sets `state_since = now` and fires `EVENT_STATE_CHANGED` with `{"room": config.name, "state": new.value, "previous": old.value, "reasons": [r.value for r in reasons]}`. On the first evaluation it sets `state_since = now` and fires nothing. Then it calls the update listeners as before. `async_start` clears `window_contact_unavailable` like the other window issues.
