# Easy TRV 0.9 — Presence controls and the Easy TRV card

Derived from the owner's decisions of 2026-11-05 and the earlier designs, above all `2026-10-18-easy-trv-0.7-presence-design.md`, which stays valid wherever this document is silent.

Goal (owner): the things set or watched most often are entities, so a card (0.10) and automations can use them. It must work as simply as possible. The owner asked to put the controls and the card into one release (2026-11-07, no hurry). Schedules from a Home Assistant `schedule` helper follow later.

Field data behind the away delay: on 2026-10-21 (19:04–19:17) and 2026-10-22 (21:25–21:36) the presence person read away for about 12 minutes and both rooms were lowered at once.

Not in this step: schedules, calendars, a forced presence per room, an away delay per room, a setback entity per room, window bypass, boost.

## 1. Away delay

- New setting `away_delay_minutes` in the integration options, section **Presence**, 0–120 minutes, default **15**. Global only, no room override. `0` = away counts at once (the behaviour of 0.7/0.8).
- **Away** (including **unknown** read as away) counts only after the presence entity has read away for the delay without a break. **Home** counts at once and cancels a running delay.
- **Start:** an entity that reads away since longer than the delay (its `last_changed`) counts as away at once; one that reads away for less counts as home until the rest of the delay has passed.
- The delay applies to every room's resolved entity (global or own), each on its own.
- While the delay runs the room behaves as home. The room's presence binary sensor (§3) has the attribute `away_from` with the time away will count; absent otherwise.

## 2. Force presence for the house

- New entity `select.easy_trv_presence` on a new device **Easy TRV** (the house). Options **Automatic** (`auto`, default), **Home** (`home`), **Away** (`away`). German: Automatisch, Zuhause, Abwesend.
- **Home** / **Away** override what every room with presence reads, at once and without the away delay. Rooms without presence (`presence: none`, or Global without a global entity) are not affected.
- **Ends by itself:** the select returns to **Automatic** when the global presence entity changes between home and away (its raw state, before the delay and after the unknown policy). Without a global entity it stays until set back. A change of a room's own entity does not end it.
- Effect in the room as in 0.7: home ↔ away writes the new target (Lower) or starts/ends the hold (Off). A target set while forced away is an override as in 0.7 §3 and ends when the room reads home.
- **Restart:** the select restores its option together with the raw presence it saw when it was set. If the global entity reads differently at start, the select returns to **Automatic**.
- Attributes: `presence_entity` (the global entity or absent), `forced_at` (time the option was set, absent on Automatic).
- Heating-state hint: while forced, the hint names "Easy TRV presence" instead of the entity (German "Easy-TRV-Anwesenheit").
- Bus event `easy_trv_presence_forced` with `option` (`auto`, `home`, `away`) and `reason` (`user` or `presence_changed`).

## 3. Entities per room

Both on the room device, read-only, `entity_category` none (so a dashboard shows them):

| Entity | Exists when | On | Attributes |
|---|---|---|---|
| `binary_sensor.<room>_window`, device class `window` | the room has window contacts | any contact reads open (no opening delay) | `contacts_open` (list of open contacts) |
| `binary_sensor.<room>_presence`, device class `presence` | the room has presence | the room reads home (after the delay, forcing applied) | `source` (`entity` or `forced`), `presence_entity`, `away_from` (§1) |

The room thermostat keeps its attributes `presence`, `away_target` and `away_override`.

## 4. Setback as an entity

- New entity `number.easy_trv_away_setback` on the house device, 0.5–10 K, step 0.5, unit K, mode box, `entity_category` config. It shows and sets the **global** `away_setback_kelvin`.
- Rooms with their own setback keep it; the number does not change them. Its attribute `rooms_with_own_setback` lists them, so the card can say so.
- **No reload:** a change writes the option, and Easy TRV applies it to the running rooms instead of reloading. Rooms that are lowered get the new target written at once. The same holds when only `away_setback_kelvin` and/or `away_delay_minutes` change in the options form; any other change reloads as before.

## 5. Settings

| Key | Where | Values | Default |
|---|---|---|---|
| `away_delay_minutes` | options, section Presence | 0–120 min | 15 |

The select's option is runtime state (restored), not a setting.

## 6. Core design

- No change to the room core: it keeps receiving `PresenceChanged(away)` and `Start(away=…)`. Delay and forcing live on the Home Assistant side and decide what is fed.
- `RoomConfig.away_setback` changes at runtime through a new event `SettingsChanged(away_setback)`: the room swaps the value and, if its target changes, writes it like a presence change (same path as `hold.on_presence` with a changed target).

## 7. Home Assistant side

- **`HousePresence`** (new, in `observation.py` or its own module), one per config entry in `runtime_data`: holds the forced option, tracks the global entity's raw state to end forcing, restores via the select, notifies the rooms' presence inputs on a change.
- **`PresenceInput`** gets the delay (`async_call_later`, cancelled on home, on stop and on unload) and asks `HousePresence` for a forced value before its own. It feeds `PresenceChanged` only when the effective value changes.
- **House device:** identifiers `(DOMAIN, entry_id)`, manufacturer Easy TRV, name "Easy TRV". New platforms `select`, `number`, `binary_sensor`.
- **Reload listener:** compares old and new options and subentries; when only the live keys of §4 differ it calls the controllers instead of `async_schedule_reload`.
- Diagnostics: forced option, `forced_at`, delay, per room the effective presence and `away_from`.

## 8. Tests

HA side: delay (away after the delay, home cancels, unknown delayed, start with an old and with a fresh away, `0` = at once, stop cancels the timer), forcing (home/away override, rooms without presence untouched, ends on a change of the global entity, not on a room's own, stays without a global entity, restore with same and changed raw presence, event), binary sensors (exist only when configured, states and attributes), number (writes the option, no reload, lowered rooms get the new target, rooms with their own setback unchanged and listed), reload listener (live keys only vs. any other change), translations DE/EN, diagnostics. Core: `SettingsChanged` while lowered, while home, while off-hold, with an override.

## 9. The Easy TRV card

Owner: it must work as simply as possible. The details below were decided by the maintainer on the owner's behalf (2026-11-07); the owner can correct them in review.

### 9.1 Delivery

- The card ships inside the integration (`custom_components/easy_trv/frontend/easy-trv-card.js`), so HACS installs it with Easy TRV and both always have the same version (Better Thermostat broke cards when the two drifted apart).
- At setup Easy TRV serves the file under `/easy_trv/easy-trv-card.js` (`hass.http.async_register_static_paths`) and loads it as a frontend module (`frontend.add_extra_js_url`) with `?v=<version>` against stale caches. Nothing to add under dashboard resources. Manifest `dependencies` gain `http` and `frontend`.
- One plain JavaScript file, no build step: a web component that uses Home Assistant's own elements (`ha-card`, `ha-icon`, `ha-state-icon`) and registers itself in `window.customCards`, so it appears in the card picker as "Easy TRV".

### 9.2 Configuration

- `type: custom:easy-trv-card` without anything else shows the house row and every Easy TRV room, in the order of the integration's rooms.
- Optional: `rooms:` (list of room thermostat entities, filters and orders), `house: false` (hide the house row), `statistics: false` (never show the statistics part).
- The card finds everything itself from `hass.entities` / `hass.devices`: entities of the platform `easy_trv`, grouped by device (house device, one device per room). A missing entity (statistics off, no contacts, no presence) just hides its part.
- A visual editor offers the same three options.

### 9.3 House row

- Presence: the select of §2 as three buttons (Automatic, Home, Away); the active one is marked, a forced option shows "erzwungen seit HH:MM".
- Setback: the number of §4 with − / + in 0.5 K steps; a hint when rooms have their own setback.

### 9.4 One block per room

- **Top line:** room name, current temperature (the room thermostat's `current_temperature`), target with − / + (step of the room), mode buttons Heat / Frost / Off (the room thermostat's HVAC modes).
- **Status line:** icons for window open (§3), away/home (§3, with "ab HH:MM abwesend" while the delay runs), lowered target (`away_target`) and the heating-state text.
- **Why line:** the heating state's `hint` in plain text, shown only when the state is not `heating` (for example "Abgesenkt: abwesend (person.oliver_markantelli)", "Notbetrieb: …").
- Colour: the heating state's group (normal, lowered/off, restricted, fault) tints the block's edge.
- Tap on the room name opens the room thermostat's more-info dialog.

### 9.5 Statistics (collapsed)

- Per room a "Statistik" toggle, collapsed by default. It shows, when the sensors exist: control deviation, heating time, window open time, and per thermostat writes failed and dropouts only when above 0.
- No charts in this step; a tap on a value opens its more-info dialog with Home Assistant's history.

### 9.6 Tests

- Python: the static path and the module URL are registered once per setup and the version is in the URL; manifest dependencies.
- Card: a small test with the frontend test runner is out of scope for 0.9; instead a manual check list in `docs/testing-on-device.md` (no config, `rooms:` filter, a room without contacts/presence/statistics, forcing presence, setback, target and mode, dark theme, phone width).
