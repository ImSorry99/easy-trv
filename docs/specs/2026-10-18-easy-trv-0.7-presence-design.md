# Easy TRV 0.7 — Presence: lower or switch off rooms while nobody is home

Derived from the owner's decisions of 2026-10-18 and the earlier designs (`2026-10-14-easy-trv-phase2-design.md`, `2026-10-15-easy-trv-0.5-room-state-design.md`, `2026-10-15-easy-trv-0.6-statistics-design.md`), which stay valid wherever this document is silent.

Goal (owner): presence detection has priority. First step: Easy TRV reads presence from an entity the user chooses. Most installations use one global entity; a room can use its own or none. While away, a room is either lowered by a number of kelvin or switched off, and the user chooses which.

Not in this step: vacation with a return time and preheating, a delay before "away" counts, schedules. A local branch (`feat/0.7-presence`, never pushed) explored a house-wide design with vacation; this design replaces it.

## 1. Where presence comes from

- **Global entity** in the integration options, new section **Presence** (`presence_entity`, entity selector). Most rooms use it.
- **Per room** in the room settings: `presence` = **Global** (default) / **None** / **Own**, and `presence_entity` for **Own**. **None** ignores presence for the room. A room with **Global** and no global entity has no presence.
- **Accepted domains and what reads as home:**

  | Domain | Home | Away |
  |---|---|---|
  | `person`, `device_tracker` | `home` | any other state (`not_home`, a zone name) |
  | `zone` (for example `zone.home`) | a number above 0 | `0` |
  | `group` | `home` or `on` | `not_home` or `off` |
  | `binary_sensor`, `input_boolean` | `on` | `off` |

  Anything else (`unknown`, `unavailable`, a missing entity, an unexpected value) is **unknown**.
- **Unknown** reads as set in `presence_unknown`: **Away** (default, owner: unknown is not home) or **Home**. Global with a room override.
- "Away" counts at once; a delay can be built in Home Assistant (template or group helper).

## 2. What away does

Setting `away_action` (global, room override): **Lower** (`setback`, default) or **Off** (`off`).

- **Lower:** the thermostats get the room's wish minus `away_setback_kelvin` (0.5–10 K in 0.5 K steps, default 3 K), never below the frost protection temperature and never above the wish (a wish below frost stays as it is). The value is rounded to the room's step and clamped to its range. The room thermostat keeps showing the wish; the value sent is the attribute `away_target`.
- **Off:** a hold like an open window or the outdoor cut-off: every thermostat is switched off, those on their schedule included (they stay off afterwards, as with the other holds), and the room's wish comes back when the hold ends. It is a third hold beside window and outdoor; the room returns when all are clear.
- **Home again:** the wish (target and mode) is written back.
- Presence only acts while the operating mode is **Heating enabled**. **Off** stays off; **Frost protection** is already below any lowering.

## 3. Override while away

- A new target while away — set in Home Assistant or turned at a knob (a settled knob turn, as the room already adopts them) — is an override: the room heats normally to the new target until presence turns home. The next time everybody leaves, presence acts again.
- With **Off**, the same override ends the away hold (a knob turn during the window or outdoor hold still only changes the wish).
- The override survives a restart (restore data of the room thermostat). It ends when presence reads home.
- A thermostat that reports the old wish while the room is lowered (a sleepy thermostat that has not taken the lowered value yet) is drift and gets the lowered target again; only a settled turn to a third value is an override.
- Known limit: a first start without restore data while away adopts the first thermostat's setpoint as the wish; if that thermostat still shows a lowered value, the wish is that value until someone sets one.

## 4. What the room shows

- **Heating state:** `off_away` (exists as a placeholder) while the away hold is active; new `setback_away` ("Abgesenkt: abwesend" / "Lowered: away") while the room is lowered by more than 0. Both appear in `reasons`; `setback_away` sits after `boost` and before `frost` and `heating`. The hint names the presence entity.
- **Room thermostat attributes:** `presence` (`home`, `away` or `none` for a room without presence), `away_target` (the value sent while lowered, else absent), `away_override` (true while an override holds).
- **Bus event** `easy_trv_away` with `room` and `state` (`on` when away starts to act, `off` when it ends), like `easy_trv_window_hold`.
- **Statistics:** the control deviation measures against the value sent (lowered target) while lowered; no deviation during the away hold (as during the other holds).

## 5. Settings

| Key | Where | Values | Default |
|---|---|---|---|
| `presence_entity` | options (section Presence); room with `presence: own` | an entity of the domains above | none |
| `presence` | room only | `global`, `none`, `own` | `global` |
| `presence_unknown` | options, room override | `away`, `home` | `away` |
| `away_action` | options, room override | `setback`, `off` | `setback` |
| `away_setback_kelvin` | options, room override | 0.5–10 K, step 0.5 | 3.0 |

The options form gets a collapsed section **Presence** with the global entity and the three settings. The room settings get `presence`, `presence_entity` and the three overrides (Global first, as for every setting).

## 6. Core design

- `RoomConfig`: `away_action: Literal["setback", "off"] | None` (`None` = no presence for the room), `away_setback: float`.
- `RoomState`: `away: bool` (presence reads away after the unknown policy), `away_override: bool`.
- Event `PresenceChanged(away: bool)`; `Start` gets `away: bool` for the value at start. The Home Assistant side resolves the entity and the unknown policy; the core only sees away or home.
- `setpoint.target(cfg, state)`: the value the thermostats should show; the wish unless the room is lowered (`away`, `away_action == "setback"`, no override, operation heat). Every place that writes or compares the setpoint uses it: writes, resume, retries, reconciling and in-sync checks, observe (echo and drift), statistics.
- `holding(state)` includes the away hold (`away`, `away_action == "off"`, no override). The hold transitions of `core/hold.py` apply unchanged.
- A setpoint from Home Assistant or an adopted knob turn while presence acts sets `away_override`; `PresenceChanged(False)` clears it. Changing between home and away writes the new target (lower) or starts/ends the hold (off).
- Heating state: facts `away_hold` and `away_lowered` (`target < wish`).

## 7. Home Assistant side

- `PresenceInput` in `observation.py`, like the outdoor sensor: tracks the room's resolved entity, maps its state per domain, applies `presence_unknown`, feeds `PresenceChanged` only on a change, and gives the value at start.
- Rooms without presence (`away_action is None`) track nothing.
- Restore: the room thermostat's extra data gets `away_override`.

## 8. Tests

Core: target arithmetic (floors, rounding, range, wish below frost), writes on away/home, override by HA and knob, override cleared on home, off as a hold together with window and outdoor, restart restore, heating states. HA: domain mapping, unknown policy both ways, global vs own vs none, form fields and translations, attributes and event, diagnostics.
